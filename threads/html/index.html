Re: Is C still relevant for compiler construction? — John McCarthy <jmc@stanford.edu> 1995-03-12
C remains the lingua franca for systems programming. Most production compilers are still written in C or C++. The real question is whether that *should* continue to be the case.
Re: Is C still relevant for compiler construction? — Alice Lang <alang@mit.edu> 1995-03-13
I'd argue ML-family languages are far better suited for writing compilers. Pattern matching on AST nodes alone makes it worthwhile. SML/NJ is itself a compelling example.
Re: Is C still relevant for compiler construction? — Bob Parse <bparse@bell-labs.com> 1995-03-14
Pattern matching is nice, but try getting ML to emit fast native code on 15 different architectures. GCC's C codebase is ugly but it *works* everywhere.
Re: Is C still relevant for compiler construction? — Alice Lang <alang@mit.edu> 1995-03-15
Fair point on portability. But that's an argument for better ML backends, not for writing new compilers in C.
Re: Is C still relevant for compiler construction? — Carol Lex <clex@cmu.edu> 1995-03-13
Don't overlook Lisp. The Lisp community has been writing compilers in Lisp since the 1960s. Macros give you AST manipulation for free.
